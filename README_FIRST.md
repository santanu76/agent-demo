# acmehealth — AiGenie agent workspace

This is **your** repo now — nothing here is read back by AiGenie, ever.
Generated by the Hub, but from this point on it lives, builds, and deploys
entirely under your own control.

## First time here

### 0. Connect to AiGenie's private package index (one-time per machine/CI)

`aigenie-sdk` — the wire-contract library `adapter.py`/`field_selector.py`
import — is published to AiGenie's private package index, not public
PyPI. AiGenie gives you an IAM access key scoped **read-only** to this one
package, revocable any time from AiGenie's side without needing you. With
the AWS CLI installed:

```
export AWS_ACCESS_KEY_ID=<the key id AiGenie gave you>
export AWS_SECRET_ACCESS_KEY=<the secret AiGenie gave you>
aws codeartifact login --tool pip --domain aigenie \
    --domain-owner 818561370937 --repository aigenie-sdk \
    --region ap-south-1
```

This writes a short-lived (12h) token into your pip config. Re-run it
whenever `pip install` stops finding `aigenie-sdk` again — nothing else
about the commands below changes.

```
git init
git add .
git commit -m "AiGenie-generated agent workspace"
git remote add origin <your own empty repo's URL>
git push -u origin main
pip install -e .
python -m pytest   # fails until the TODOs below are done — that's expected
```

Work through these in order; each file says exactly what to edit.

| # | File | What you do |
|---|------|-------------|
| 1 | `acmehealth/adapter.py` | map YOUR request fields to the AiGenie shape (TODOs marked) |
| 2 | `acmehealth/response_mapper.py` | shape AiGenie cards into YOUR UI JSON (examples inline) |
| 3 | `acmehealth/agents/*_agent.py` | your business logic inside the >>> markers |
| 4 | `acmehealth/tools/*_tool.py` | your integrations inside the >>> markers |
| 5 | `acmehealth/master_agent.py` | routing between AiGenie and your agents (optional) |
| — | `acmehealth/field_selector.py` | DO NOT EDIT — regenerate from the Hub's API Contract page |

Once an agent is deployed somewhere reachable, paste its URL into that
agent's `endpoint_url` back in the Hub's Agent Registry — that's the only
thing that connects this repo to AiGenie at runtime. AiGenie's own service
never executes any code in this repo; it only ever calls the URL you give it.

**Secrets:** if your business logic calls your own APIs, read credentials
from your own environment/secrets manager — never commit a key into this
repo.

## Keeping it up to date

If you change something in the Hub that affects generated files (a new
attribute, a changed card schema), download the **regen bundle** instead
of the full workspace — it contains only the files marked DO NOT EDIT
above. Drop them into this same checkout, overwriting in place, then
`git diff` to see exactly what changed before you commit. Your own
business logic in `agents/`, `tools/`, `adapter.py` and
`response_mapper.py` is never touched by a regen bundle.
